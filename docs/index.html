Four Pillars of
Control Assurance

OCEAN isn't a GRC platform. It's the evidence and verification layer that GRC platforms should consume. Pair it with Corsair for audit-grade cryptographic provenance.

🔭
PILLAR 01
Passive Control Monitoring

Query system APIs to observe configuration state without modifying anything. Evidence is normalized, immutable, and stored with full provenance metadata. Confidence level: passive_observation.

ocean observe --target okta --control iam.mfa
⚔️
PILLAR 02
Active Control Testing

Attempt what controls should prevent — like Atomic Red Team, but for compliance. Every tester declares a safety classification. Confidence level: active_verification.

ocean test okta.mfa_bypass
🧮
PILLAR 03
Flexible Evaluation Logic

Define compliance conditions using CEL expressions or structured YAML presets. Write exactly the logic your organization requires — no vendor lock-in, no black boxes.

ocean evaluate --cel '...'
🔗
PILLAR 04
Cryptographic Provenance

OCEAN pipes evidence to Corsair — an open-source signing tool that produces W3C JWT-VC Certificates of Proof of Operational Effectiveness (CPOEs). Any auditor can verify independently.

ocean observe --target okta --control iam.mfa | corsair sign

Seven Assessment Activities
1 config_inspection — read-only API observation
2 resource_enumeration — list and count resources
3 log_query — mine audit / SIEM data
4 behavioral_test — active control exercise
5 bypass_attempt — try what controls prevent
6 probe — network / API reachability test
7 population_analysis — fleet-level compliance %
Evidence is framework-agnostic. Controls map to SOC 2, ISO 27001, NIST, PCI-DSS etc. in YAML control files — not in the evidence schema itself.

// corsair integration

Audit-Grade Provenance
Powered by Corsair

OCEAN produces structured, normalized evidence. Corsair turns it into independently-verifiable Certificates of Proof of Operational Effectiveness (CPOEs) — W3C JWT-VC format, Ed25519 signatures. Any auditor can verify without trusting you.

✓ Pipe OCEAN output directly to Corsair CLI
✓ W3C JWT-VC format — standard, portable, auditable
✓ Auditors verify CPOEs without running OCEAN
✓ Open-source — grcorsair.com
01
Collect & Test

OCEAN queries APIs and runs active testers. Evidence normalized to schema.

ocean verify control.mfa_enforcement --output json
02
Pipe to Corsair

OCEAN output streams directly into Corsair for signing — no intermediate files needed.

ocean verify ... | corsair sign --mapping-pack ocean
03
CPOE Issued

Corsair produces a W3C JWT-VC Certificate of Proof of Operational Effectiveness.

cpoe.jwt — Ed25519 | iss: did:key:z6Mk… | exp: 90d
04
Independent Verification

Any auditor verifies the CPOE against your DID. No OCEAN required, no trust assumed.

corsair verify cpoe.jwt --issuer did:key:z6Mk…
