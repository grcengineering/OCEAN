### 3. Spec-Kit Skills Issues

**Problem**: The spec-kit commands (e.g., `/speckit.constitution`) are installed as Claude Code command files in `.claude/commands/`, but they are NOT registered as invocable skills.

**Attempted Solutions:**
1. `Skill("speckit.constitution", args)` → Error: "Unknown skill: speckit.constitution"
2. `Skill("speckit:constitution", args)` → Not tried, would also fail
3. Directly invoking the command files is not supported by the Skill tool

**What Worked:**
- Reading the command file templates to understand the expected format
- Manually writing the spec artifacts following the template structure
- All artifacts were created successfully by direct file writes

**Root Cause Analysis:**
The `speckit-autopilot` skill is registered (it's in `~/.claude/skills/`), but the individual spec-kit commands from `.claude/commands/` are not exposed as skills. These command files appear to be meant for manual slash-command invocation (`/speckit.constitution`) rather than programmatic skill invocation.

**Recommendation for Future Sessions:**
1. Either manually invoke `/speckit.constitution` etc. as slash commands
2. Or write spec artifacts directly following the templates (which is what this session did)
3. The speckit-autopilot skill watches for triggers but doesn't provide the underlying commands

## Research Summary for Future Reference

### The Problem OCEAN Solves

From user's blog post, SOC 2 has three fundamental flaws:
1. **Vague control requirements** - Trust Services Criteria lack connection to specific threats
2. **Inadequate audit methods** - Technical controls assessed point-in-time, not historically
3. **Static reports** - Reports become outdated within weeks

Current "Trust Center" products are "pure theater" - they hide failing controls and show only current state.

### The Vision

OCEAN enables the ALCOVE concept (Assurance Levels for Control Operating Viability & Effectiveness):
- **Multi-level assurance** like SLSA for supply chain
- **Threat-informed controls** with specific requirements
- **Dynamic dashboards** replacing static PDFs
- **Full population analysis** instead of sampling
- **Historical evidence** proving continuous effectiveness

### Schema Design (OCSF-Inspired)

Evidence organized as:
- **Categories** (Control Domains): IAM, Network, Data, Endpoint, Cloud, App, Ops, Compliance
- **Classes**: Specific evidence types within domains
- **Attributes**: Fields with consistent semantics across all evidence
- **Profiles**: Cross-cutting concerns (audit trail, temporal, enrichment)
- **Extensions**: Regulation-specific additions without core changes

### Architecture (Metasploit-Inspired)

- **Collectors** = Modules (self-contained, interface-compliant)
- **Core** = Framework (orchestration, storage, evaluation)
- **Controls** = Rules (declarative YAML definitions)
- **Registry** = Module discovery and loading

## Appendix: Full Research Notes

### OCSF Key Concepts
- `class_uid` + `category_uid` + `activity_id` = unique event type
- `type_uid` = (class_uid × 100) + activity_id
- Enum values: 0=Unknown (default), 99=Other (with string sibling)
- Temporal: original_time, time, processed_time, logged_time, modified_time
- Observables array surfaces all indicators regardless of nesting

### Existing Tool Analysis

**GovReady-Q**: OSCAL/OpenControl focus, self-service assessments, FedRAMP-oriented
**CISO Assistant**: 70+ frameworks, NIST OLIR mappings, CLI automation, REST API
**Eramba**: Policy/risk management, internal audits, ISO 27001/GDPR focus
**GigaChad GRC**: Full platform (controls, risks, vendors, audits), React/Node/PostgreSQL

**OCEAN differentiator**: Not a full GRC platform - just the evidence acquisition and normalization layer that platforms consume.

### Control Example: WAF Protection

A composite control proving WAF is correctly implemented:
1. **Cloudflare evidence**: WAF enabled, rules in blocking mode, OWASP ruleset active
2. **DNS evidence**: Domain resolves to Cloudflare proxy (orange cloud)
3. **AWS evidence**: Security Group allows only Cloudflare egress IPs
4. **Certificate evidence**: Valid TLS cert, not expired

All four must be effective for the control to be effective.
